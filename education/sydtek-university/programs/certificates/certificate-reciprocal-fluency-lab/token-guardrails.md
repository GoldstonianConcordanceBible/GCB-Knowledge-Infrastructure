# Token Guardrails

## Purpose

This document prevents the SydTek Fluency Lab from repeating the failures of past learn-and-earn token models.

## Core Rule

The program must never become token-first.

The program is certificate-first, fluency-first, and proof-first.

## Token Role

Any token used in the system should function as:

- Recognition
- Access
- Governance support
- Scholarship support
- Contribution tracking

It should not function as a guaranteed wage.

## Never Do This

Do not create rewards for:

- Clicking lessons
- Watching videos
- Daily login streaks
- Empty attendance
- Fake referrals
- Low-quality mass participation

## Approved Token Uses

Token utility may include:

- Applying for advanced certification
- Accessing premium fluency pods
- Voting on approved curriculum topics
- Funding learner scholarships
- Recognizing verified mentors
- Recognizing approved translation work

## Emission Limits

Token rewards must be:

- Scarce
- Capped
- Periodic
- Governed
- Tied to verified outcomes

## Anti-Dump Design

The system should avoid creating users who only join to extract and leave.

Use:

- Vesting
- Reputation requirements
- Level gates
- Mentor status requirements
- Contribution verification
- Non-transferable reputation badges

## Core Principle

The token must serve the certificate.

The certificate must never serve the token.
